# 前端 Sprint 17：站内消息（对齐后端 U）

> **编号**：`plan/frontend/17`  
> **状态**：排队（等后端 [U](../backend/21-sprint-u-oa-message.md) 的 U1/U2）  
> **目标**：顶栏能看未读消息，标已读，并能从消息跳到任务或待办。指派、逾期、审批结果会进收件箱。  
> **不做**：企业微信模板卡片、扫码登录、OAuth2 客户端管理（U3/U4 无企业微信可不做页面）。

---

## 0. 范围

```text
F17-1  api：我的消息、标已读
F17-2  顶栏铃铛：未读数、下拉或抽屉列表
F17-3  点击按 bizType 跳转
F17-4  自测三条业务：指派、逾期、审批通过/驳回
```

**协作**：铃铛壳由助手写；未读过滤与跳转搜 `【学员填写】`。

---

## 1. 后端接口速查

| 动作 | 方法 | 路径 |
|------|------|------|
| 我的消息 | GET | `/oa/message/my`（未读在前） |
| 标已读 | PUT | `/oa/message/read` body 为 id 列表，只能改自己的 |

消息字段预期：接收人、标题、内容、已读、`bizType`、`bizId`。真实字段以实体为准。

`bizType` 约定（后端 U2）：

| bizType | 何时产生 | 前端跳转 |
|---------|----------|----------|
| `task_assign` | 任务执行人不是创建人 | 任务列表或详情，带 taskId |
| `task_overdue` | 逾期 Job 之后 | 同上 |
| `approve_pass` / `approve_reject` | 办理结束 | 待办或已办 |

没有 bizId 就只打开详情，不跳。

## 2. 前端落位

```text
taskforge-ui/src/
  api/oa/message.js
  layout/index.vue            # 铃铛
  components/oa/MessageDrawer.vue
```

不单独做侧栏菜单，除非库里已有「我的消息」菜单，那时再加 `views/oa/message/index.vue` 复用同一列表。

---

## 3. 分阶段要点

- 未读用红点或数字；点一条即 `read`，或提供「全部已读」。
- 列表空状态写「暂无消息」。
- 跳转失败（任务已删）停留在抽屉并提示，不要把整站弄到 404 空白。
- 逾期消息依赖 Job，自测可在定时任务页对逾期扫描点「执行」后再刷新铃铛。

---

## 4. 验收标准

- [ ] 给我指派任务后，执行人铃铛出现 `task_assign`
- [ ] 逾期执行后，执行人能看到逾期消息（审批中被跳过的任务不应出现）
- [ ] 审批通过/驳回后，发起人能看到对应消息
- [ ] 标已读后未读数下降，刷新仍保持已读

```bash
cd taskforge-ui && npm run dev
```
