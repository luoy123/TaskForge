# 前端 Sprint 19：异步投递运维（对齐后端 W，可选）

> **编号**：`plan/frontend/19`  
> **状态**：可选（等后端 [W](../backend/23-sprint-w-async-mq.md)）  
> **目标**：给管理员看失败的异步消息，并手工重新入队。不做也不影响 L～V 的业务验收。  
> **前置**：U 的发送已改成先入 `pmhub_async` 表。  
> **不做**：RocketMQ 控制台、在业务页展示队列。

---

## 0. 范围

```text
F19-1  失败（及可选全部）列表
F19-2  单条重放
F19-3  菜单仅管理员 / 权限字
```

**协作**：表格壳由助手写；列表与重放搜 `【学员填写】`。

---

## 1. 后端接口速查

| 动作 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 列表 | GET | `/tool/async/list?status=` | 分页。`0` 待处理，`1` 成功，`2` 失败 |
| 重放 | PUT | `/tool/async/retry/{id}` | 只把 status 改回 0、次数清零，**本请求里不发送** |

列：topic、body 摘要、status、retryCount、错误信息、创建时间。body 可能是 JSON，表格里截断，点开再看全文。

## 3. 分阶段要点

- 默认筛 `status=2`。
- 重放二次确认，成功提示「已重新入队，等待任务扫描」。
- 刷新后该行应变为待处理或成功；不要在点击后前端自己把消息插进收件箱。
- topic 固定 `site_message` 时，列上可显示中文「站内消息」，其它 topic 原样显示。

---

## 4. 验收标准

- [ ] 能看到失败记录及错误信息、重试次数
- [ ] 重放后状态离开「失败」，最终能成功（Job 在跑的前提下）
- [ ] 普通无权限用户打不开或 403
- [ ] 页面没有「安装 RocketMQ」之类引导

```bash
cd taskforge-ui && npm run dev
```
